# KIT-ADR-0034: What is allowed to generate kit work

**Status**: Proposed
**Type**: **Governance / policy** — unlike KIT-ADR-0030–0033, this
decision does not compile. Its enforcement is the WIP cap, the shared
queue, and the acceptance test below; its failure mode is quiet
reversion, which is why its revisit trigger is quantitative.
**Date**: 2026-08-13 (drafted 2026-08-09 as part of a combined ADR; split
per operator decision — see KIT-ADR-0030 Provenance)
**Deciders**: Fredrik Matheson (operator), Claude Code
**Related**: KIT-ADR-0027 P4b (retro-closure lifecycle — the standing
substitute for audits), KIT-ADR-0030/0031 (the moves that make live
intakes the kit's real test surface), PR-SIZE-WORKFLOW review-surface
budget + bot-triage self-churn circuit breaker (2026-08-10 — the same

## Context

Kit work has been generated by **auditing the kit**. The 2026-07-24
pre-0.9.0 sweep produced 92 confirmed findings (40 stale-doc, 29
contradiction, 15 version-drift, 6 orphan) and spawned four tasks —
work generated by inspecting the kit rather than by using it.

Compare KIT-0081: one live intake (`ev-fast-charging-loads`,
2026-08-04) produced nine concrete gaps, none blocking, all small,
every one traceable to a moment that cost the operator something. An
audit surfaces every statement that has gone false. A live run surfaces
the ones that are load-bearing. Those are different sets, and only the
second is bounded by demand.

The kit is its own only consumer, so "wrong" has had no victim outside
the kit — which is how audit-driven work came to be the default
generator.

**The rule was demonstrated before it was written.** Between the
combined draft and its review, the operator ran a live `/new-project` +
`/setup-preset` test (2026-08-11). It produced four findings (F7–F10),
every one an experience the operator actually had, none a false
statement an audit would have ranked. They became KIT-0100 and KIT-0101
and shipped inside two days. One live run, four findings, two days to
fixed: the generator works.

## Decision

> Kit work is triggered by a defect that blocked or degraded a real
> project intake, or by a release obligation. Not by an audit.

Supporting mechanics:

- **One queue.** Project work and kit work share a backlog. Kit work
  currently has no competing entries, so it does not win — it runs
  unopposed.
- **A WIP cap**: at most two open kit tasks not traceable to a live
  project. This ADR set follows its own rule — it files KIT-0104 and
  KIT-0105 only; the remaining decisions are sequenced and filed as
  their predecessors land.
- **Demand-reduction mechanisms count as supporting this rule**, not as
  exceptions to it. The review-surface budget and the self-churn
  circuit breaker cap work the kit generates *against itself*; KIT-0098
  is the pattern working.
- **Automation replaces sweeps.** `doctor.d/`, `plugin-drift.yml`, and
  the retro-closure lifecycle rule are the standing substitute for
  periodic audits, not a complement to them. Every check added there is
  a sweep never run again.
- **The premise challenge stays.** Testing the premise of open backlog
  items and archiving with evidence-bearing dispositions is
  demand-reduction, not generation.

An audit is not forbidden; it stops being the default. Running one is
itself a decision that should name what changed to justify it.

### The enforcement mechanism: the intake acceptance test

Extend `tests/test_scaffold_acceptance.py` to run the full intake
end-to-end in CI against a fixture prototype folder: create → `agentive
doctor` → **assert every file path referenced by the seeded agents
exists in the created tree**.

That last assertion is KIT-0081 F2 — found by hand, by grepping the
seeded agents for `docs/…` and `.kit/…` paths and testing existence; it
caught a planning scaffold shipping without the document its own seeded
planner routes every git operation by. A machine should do that on
every push.

**When this test is green, the kit does not need visiting.** That is
what makes the policy above safe to hold to — the executable definition
of "the kit works" replaces the audit as the standing answer to "is
anything broken?". The test rides the intake move (KIT-ADR-0031's
task); it is sequenced, not separately filed, per the WIP cap.

## Consequences

**Positive**

- Kit work becomes bounded by demand instead of by how much staleness a
  sweep can surface.
- The invariant previously enforced by audit is enforced by machinery —
  the correct pattern-match to KIT-ADR-0027 P4b.

**Negative / risks**

- Some true-but-unimportant staleness will persist. That is the
  intended trade. The cruft audit's own distribution — 40 of 92
  findings stale-doc — is the evidence that sweeping is unbounded.
- The WIP cap is enforced socially. With one operator that is
  acceptable; see the revisit triggers.

## Revisit Triggers

- **Kit tasks exceed the WIP cap for two consecutive months** — the cap
  is wrong, or the generator rule is being routed around. Either way
  the policy needs redeciding, not quiet exceptions.
- **agentive-starter-kit itself splits** (see KIT-ADR-0032's trigger) —
  the kit would finally consume the topology it ships, giving "wrong" a
  victim outside the kit. Revisit both ADRs together; this likely lets
  the WIP cap tighten.
- A second operator — social enforcement of the cap needs dashboarding.
